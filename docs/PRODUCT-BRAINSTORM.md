# 产品头脑风暴：创作者 AI Agent 工作台

> 状态：设计假设稿，未做市场验证。文中所有比例、时长、价格为待验证假设，不是调研结论。
> 配套技术方案见 `../ARCHITECTURE.md`。

## 1. 一句话定位

给中长视频知识型创作者用的「项目制 AI 制作台」：从选题到发布包，一条流水线跑完，素材不出本机，Agent 能真正读写你的文件和浏览器。

不是聊天框，不是剪辑器，不是单点文案工具。

## 2. 先划清边界：这个赛道哪里是空的

创作者工具整体极度拥挤：剪辑有剪映/CapCut/Descript，录屏有 OBS，选题有各种热点榜，文案有一堆 AI 写作站，短视频切片有 Opus Clip 类产品。

空位不在「再做一个生成器」，而在下面这个组合：

| 现有工具做的事 | 没人做好的事 |
|---|---|
| 生成一段文案 | 维护一个项目的完整上下文（选题依据、参考资料、脚本版本、镜头清单、封面方案、发布记录） |
| 处理一个片段 | 跨文件、跨软件执行：读素材目录、调 ffmpeg、开浏览器查资料、把结果写回项目 |
| 单次对话 | 可中断、可恢复、可审阅、可追责的多步任务 |
| 通用助手 | 懂平台规则、懂账号调性、懂历史数据表现的专用 Agent |

所以差异化不是「AI 更强」，而是三件事：项目记忆、真实执行力、人的审阅位置。

## 3. 目标用户

### 3.1 首选 ICP（MVP 只服务这一层）

- 平台：B 站知识区/科技区、YouTube 教育类。
- 粉丝：1 万–30 万。
- 形态：8–30 分钟中长视频，周更或双周更。
- 团队：1–2 人，通常自己写稿、自己剪或外包剪辑。
- 现状：用 Notion/飞书文档写稿，用表格管选题，用微信传素材，靠记忆和感觉复盘。
- 付费特征：已经在为素材站、字体、音乐、剪辑外包付费；一条商单收入可覆盖一年工具费。

### 3.2 暂不服务

- 纯短视频带货（需求是批量混剪，逻辑完全不同）。
- MCN 机构（要的是多账号矩阵和审批流，会把产品拖成后台系统）。
- 纯娱乐/生活记录（对文本和调研依赖低）。
- 完全零基础新手（没有稳定工作流，教育成本高于付费意愿）。

### 3.3 用户画像示例

> 小林，B 站科技区 12 万粉，单人作战。每期视频：选题 3 小时、查资料 5 小时、写稿 8 小时、做封面标题 2 小时、剪 10 小时。最痛苦的不是剪，是「资料散在 20 个标签页，写稿时要反复回找」，以及「上期数据为什么好，说不清」。

## 4. 工作流拆解与可切入环节

| 阶段 | 现在怎么做 | 耗时占比（假设） | Agent 能替代的部分 | 必须人做 |
|---|---|---|---|---|
| 选题 | 刷榜、看竞品、凭感觉 | 10% | 趋势扫描、竞品拆解、选题评分卡 | 最终拍板 |
| 调研 | 搜网页、存到文档、记来源 | 20% | 检索、去重、生成带出处的资料卡 | 判断可信度 |
| 脚本 | 从大纲到逐字稿 | 30% | 结构模板、初稿、钩子变体、口播顺稿 | 观点与个人表达 |
| 分镜 | 脑内构思、边剪边想 | 10% | 镜头清单、B-roll 建议、字幕断句 | 审美判断 |
| 包装 | 想标题、做封面 | 10% | 标题批量生成+评分、封面文案与构图 brief | 最终选择 |
| 发布 | 手动改多平台版本 | 5% | 各平台标题/简介/标签改写 | 点击发布 |
| 复盘 | 看后台数据 | 5% | 指标归因、与历史对比、下期建议 | 决策 |

结论：最值得先做的是「调研 → 脚本 → 包装」，三段合计约 60%，且都是文本+检索，Agent 优势最大；剪辑只做「指令和建议」，不碰时间线。

## 5. 竞品地图与我们的位置

| 类别 | 代表 | 强在哪 | 缺什么 |
|---|---|---|---|
| 通用 AI 助手 | ChatGPT / Claude / 豆包 | 生成质量、通用能力 | 没有项目上下文、不能碰本地文件、每次从零开始 |
| AI 剪辑 | 剪映、Descript、Opus Clip | 时间线、字幕、切片 | 不懂选题和脚本，不管发布包，不做复盘 |
| 写作工具 | Notion AI、各类写作站 | 轻量、便宜 | 单文档、无执行能力、无素材管理 |
| 创作者 OS | Notion 模板、飞书模板 | 组织信息 | 全靠人手填，没有 Agent |
| 海外 all-in-one | 部分 AI 视频工作流产品 | 流程完整 | 中文本地化弱、平台规则不适配、价格高 |

我们的位置：通用助手之上、剪辑软件之前的那一层。卖的是「一个项目的推进力」，不是「一次生成」。

## 6. 产品主张（五条）

1. **项目是一等公民**：每个视频是一个 Project，所有对话、文件、版本、数据挂在项目下，换设备可恢复。
2. **Agent 有手**：能读素材目录、跑 ffmpeg、开浏览器查资料、写回 Markdown/JSON/SRT，不只是吐文字。
3. **人只做判断**：每个关键节点停下来让你选，不替你发布、不替你花钱、不替你删文件。
4. **本地优先**：原始素材、未发布脚本默认不出本机；云端只同步结构化状态和必要文本。
5. **越用越懂你**：积累个人风格档案、禁用词、历史爆款结构，形成迁移不走的资产。

## 7. 功能地图

### P0（MVP，必须）

- 项目工作台：项目列表、阶段看板、产物区、对话区。
- 选题卡：输入方向 → 竞品扫描 + 选题评分（需求度/竞争度/可讲性/差异化）。
- 资料库：网页/PDF/视频字幕导入 → 切片 → 带出处的资料卡。
- 脚本工作台：大纲 → 逐字稿 → 钩子变体 → 版本对比。
- 事实核查：对脚本中的数字、引述、时间做来源比对，标黄待确认。
- 发布包：标题 10 个 + 评分、简介、标签、章节、封面文案 brief。
- 任务系统：可暂停、可恢复、失败重试、每步留痕。
- 模型设置：填 API Key 或选本地模型；按任务分配模型。

### P1（验证后）

- 镜头清单与 B-roll 建议。
- 字幕断句与 SRT 导出。
- 多平台改写（B 站/YouTube/小红书/公众号）。
- 数据回填与复盘报告（手动导入后台截图或 CSV）。
- 定时任务：每天早上扫选题、每周生成复盘。
- 团队协作：评论、审阅、版本合并。

### P2（有规模后）

- 云端 7x24 Agent：自动监控热点、自动初筛、自动生成日报。
- 插件市场：第三方 MCP 工具。
- 素材版权检测、AIGC 标识管理。
- 多账号矩阵与审批流（MCN 版本，独立产品线）。

## 8. Agent 编制

采用「一个制片人 + 若干专家 + 一个审片人」的 supervisor 结构，而不是让一个万能 Agent 什么都干。

| Agent | 职责 | 工具 | 输出 |
|---|---|---|---|
| Producer（制片人） | 拆任务、排顺序、控制预算、向用户汇报 | 任务编排、项目读写 | 任务计划、阶段摘要 |
| Scout（选题） | 趋势与竞品扫描、选题评分 | 搜索、网页抓取、平台数据 | `topic-card.json` |
| Researcher（资料） | 检索、去重、出处管理 | 搜索、PDF/网页解析、转写 | `research-notes.md` + 引用表 |
| Scriptwriter（编剧） | 大纲、逐字稿、钩子变体 | 风格档案、历史稿件 | `script.v1.md` |
| Director（导演） | 镜头清单、视觉建议 | 脚本、素材目录 | `shot-list.json` |
| Editor（剪辑助理） | 剪辑指令、字幕断句、章节 | ffmpeg、转写 | `edl.json` / `subs.srt` |
| Packager（包装） | 标题、封面 brief、简介、标签 | 标题库、平台规则 | `publish-pack.md` |
| Critic（审片） | 事实核查、风格一致性、合规检查 | 引用表、规则库 | `review-report.md` |

规则：

- Producer 不做内容，Critic 不写内容，写和审永远分离。
- 每个 Agent 只写自己那份产物文件，避免互相覆盖。
- 跨 Agent 只传结构化 handoff，不传整段对话历史。
- 所有 Agent 共用项目记忆，但只读自己需要的部分。

## 9. 关键体验设计

### 9.1 任务卡而不是聊天

用户看到的是「正在做什么、做到哪一步、花了多少、需要你决定什么」，不是一个不断滚动的对话框。聊天只是入口，任务卡才是主体。

### 9.2 五个必须停下来的点

1. 选题定稿（值不值得做）。
2. 大纲定稿（结构对不对）。
3. 脚本锁定（观点是否代表你）。
4. 发布包确认（标题封面）。
5. 任何对外动作（发布、发评论、付费调用、删除文件）。

### 9.3 审阅界面

左：产物 diff；右：Agent 修改理由 + 引用来源；底部：接受/拒绝/局部改写。默认不接受整段覆盖。

### 9.4 成本可见

每个任务显示预估 token 与费用，超预算前暂停询问。用户可设置「单项目月度上限」。

### 9.5 失败要可解释

任务失败时给出：哪一步、什么错、已产生哪些中间产物、重试会花多少。不允许静默失败。

## 10. 本地与云端的分工

| 能力 | 本地（未部署服务器） | 云端（部署后） |
|---|---|---|
| Agent 循环 | 本机进程执行 | 云端 worker 执行 |
| 文件读写 | 直接访问工作区 | 通过本地连接器代理 |
| 浏览器 | 本机浏览器自动化 | 云端无头浏览器 |
| 定时任务 | 仅开机时运行 | 7x24 运行 |
| 素材 | 不出本机 | 仅按需上传 |
| 模型 | API 或本地模型 | API 为主 |
| 多设备 | 不支持 | 支持 |

产品上体现为一个开关：「本地模式 / 云端增强」。用户不需要理解架构，只需要知道「关掉电脑后任务还能不能跑」。

## 11. 商业模式（待验证）

| 版本 | 价格假设 | 包含 | 目的 |
|---|---|---|---|
| Local | 免费 | 本地全功能、BYOK、无限项目 | 获客与信任 |
| Creator | ¥69/月 | 云端 30 次任务/月、20GB、定时任务 | 主力付费 |
| Pro | ¥169/月 | 100 次、多设备、协作、优先队列 | 高活跃用户 |
| Credits | 按量 | 重型任务（长视频转写、批量生成） | 覆盖成本 |

原则：

- 模型费用透明，BYOK 不赚差价。
- 按「完成的任务」而不是按 token 计费，用户可预期。
- 免费版必须能完整跑通一条视频，否则无法建立信任。

## 12. 冷启动路径

1. **先做服务，再做产品**：找 5 个 1 万–30 万粉的 UP 主，免费帮他们做 3 期视频的选题+脚本，全程录屏，提炼真实流程。
2. **用工具换案例**：把过程做成可复用的模板，换授权案例和口播推荐。
3. **内容获客**：自己开账号，发布「我用 Agent 做了一期视频」的全过程，产品即内容。
4. **社群渗透**：创作者社群、知识区 UP 主群，先给工具再谈付费。
5. **开源本地版**：本地运行时开源，建立信任，云端收费。

不建议：投信息流广告、做通用 AI 工具站、参加大赛。

## 13. MVP 范围（6 周）

只做一条链路，只服务一种内容：

```
新建项目 → 选题卡 → 资料卡 → 大纲 → 逐字稿 → 事实核查 → 发布包 → 导出
```

- 平台：先只支持 B 站知识区。
- 输入：一个主题 + 若干参考链接 + 素材目录。
- 输出：Markdown 脚本、引用表、发布包、SRT。
- Agent：Producer、Researcher、Scriptwriter、Critic、Packager 五个。
- 不做：自动剪辑、自动发布、多平台、团队协作、移动端。

验收标准：

- 一条 15 分钟视频，从主题到发布包，人工净耗时从 8 小时降到 2 小时以内（5 人实测）。
- 初稿接受率 ≥ 60%（不大改结构即可使用）。
- 事实核查能抓出 ≥ 80% 的可验证错误。
- 单条成本 ≤ ¥3（按主流 API 价格估算）。

## 14. 验证实验

| 假设 | 实验 | 通过标准 |
|---|---|---|
| 创作者愿意为「省时间」付费 | 5 人付费陪跑 | ≥3 人预付 |
| 项目制工作台比聊天更好用 | 对照测试：聊天 vs 工作台 | ≥70% 选工作台 |
| 本地优先是卖点 | 访谈 | ≥5 人主动提及隐私/素材 |
| 脚本质量够用 | 盲评 | 初稿评分 ≥ 7/10 |
| 云端定时任务有需求 | 预约 | ≥30% 愿意加价 |

## 15. 风险与反面清单

| 风险 | 说明 | 应对 |
|---|---|---|
| 平台不开放发布 API | B 站/抖音个人号基本无公开发布接口 | 只做「发布包 + 人工发布」，不承诺自动发布 |
| 平台反爬与 ToS | 抓取竞品数据可能违规 | 只抓公开页面、限频、提供手动导入 |
| AIGC 合规 | 国内要求 AI 生成内容标识 | 导出时带标识选项，保留生成记录 |
| 版权 | 素材与引用 | 只做引用管理，不做素材下载 |
| 模型成本失控 | 长上下文 + 多 Agent | 分层模型、缓存、预算上限 |
| 大厂复制 | 剪映/字节系随时加功能 | 押注个人风格资产与项目记忆，不押注单点生成 |
| 用户不愿改工作流 | 学习成本 | 从现有文档导入，不要求迁移 |
| 内容同质化 | AI 味重 | 风格档案 + 人工锁定 + 反 AI 腔规则 |

反面清单（明确不做）：

- 不做一键成片。
- 不做自动发布。
- 不做通用聊天。
- 不做素材下载器。
- 不做 MCN 后台。
- 不在第一版做插件市场。

## 16. 待决策

1. 首发平台选 B 站还是 YouTube？前者付费意愿待验证，后者 API 更开放。
2. 本地运行时用 Electron 还是 Tauri？见架构文档 ADR-001。
3. 是否开源本地版？开源利信任，但削弱商业壁垒。
4. 团队是否有剪辑/媒体处理经验？决定 P1 的边界。
5. 首发是「工具」还是「陪跑服务」？建议先服务后工具。
